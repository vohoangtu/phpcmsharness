# TZY-307 Research: autocomplete for the admin user creation password

**Research date:** 2026-11-08

## Question

Which autocomplete purpose token belongs on the static password input in `src/Presentation/Views/admin/users.php`?

## Findings

1. The WHATWG HTML Standard defines `new-password` for a new password and `current-password` for the existing password of an account, with login given as a typical current-password use. **Feature effect:** select the token from the actual form flow rather than merely from the input's password type.
   - Source: [WHATWG HTML Standard, Autofill field names](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#autofill-field-name)
   - Date: Living standard; accessed 2026-11-08.

2. MDN says `new-password` is intended for new account or password-change forms, including confirmation fields. **Feature effect:** the target form creates a new administrator/editor/author account, so its password field should advertise `new-password` to help browsers and password managers recognize a credential being created.
   - Source: [MDN: `<input type="password">`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/password)
   - Date: No publication date shown; accessed 2026-11-08.

3. MDN defines `one-time-code` for a one-time authentication code, commonly delivered out-of-band, and distinguishes it from account passwords. **Feature effect:** this field accepts a persistent account password, not an OTP, so `one-time-code` is not suitable.
   - Source: [MDN: `autocomplete` attribute](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/autocomplete)
   - Date: No publication date shown; accessed 2026-11-08.

4. MDN notes that `autocomplete="off"` is not a reliable way to prevent password manager behavior and that password managers are generally beneficial to safe password practices. **Feature effect:** declare the precise semantic token instead of disabling autocomplete or using a generic value.
   - Source: [MDN: Turning off form autocompletion](https://developer.mozilla.org/en-US/docs/Web/Security/Practical_implementation_guides/Turning_off_form_autocompletion)
   - Date: No publication date shown; accessed 2026-11-08.

## Repository assessment

The target is a literal, server-rendered form posting to `/admin/users/save`, labeled “Thêm thành viên mới” and submitted with “Tạo tài khoản”. It is account creation, not login or password reset, and the password value is entered directly in this template. The field currently has no `autocomplete` attribute. The login view already marks its existing credential as `current-password`, providing a matching local convention.

## Decision

Add `autocomplete="new-password"` to the password input. Add focused regression coverage for this static form if there is an appropriate test convention. This communicates the field's purpose to browsers and password managers; it does not guarantee runtime autofill behavior or claim full WCAG conformance.
