# TZY-306 Research: password autocomplete on the admin login form

**Research date:** 2026-11-08

## Question

Which autocomplete purpose token belongs on the static password input in `src/Presentation/Views/admin/login.php`?

## Findings

1. The WHATWG HTML Standard defines `current-password` as the current password for the account identified by the username field, with logging in as its example. The target template submits a username and password to `/admin/login`, so the field is for an existing credential. **Feature effect:** use `autocomplete="current-password"`.
   - Source: [WHATWG HTML Standard, Autofill field names](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#autofill-field-name)
   - Date: Living standard; accessed 2026-11-08.

2. MDN's password input reference recommends `current-password` when a browser or password manager should fill an existing site password, while `new-password` is for account creation or password changes. **Feature effect:** `new-password` would misdescribe this login flow; `one-time-code` is also inapplicable because this is a password field, not a one-time authentication code.
   - Source: [MDN: `<input type="password">`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/password)
   - Date: No publication date shown; accessed 2026-11-08.

3. MDN explains that autocomplete communicates the expected data to browsers and password managers and that disabling it on login fields can prevent useful autofill behavior. **Feature effect:** declare the specific purpose token rather than `off` or generic `on`.
   - Source: [MDN: `autocomplete` attribute](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/autocomplete)
   - Date: No publication date shown; accessed 2026-11-08.

## Repository assessment

The target is a literal, server-rendered administrator login form, with username and password inputs and a `/admin/login` action. The password input has no `autocomplete` attribute. The repository already uses focused markup assertions in `tests/hexagon_test.php`, so a regression assertion against the rendered login template is appropriate.

## Decision

Add `autocomplete="current-password"` to the password input and add regression coverage verifying the login password input advertises that token. This is a targeted hint for browser/password manager recognition; no claim is made about runtime autofill behavior or full WCAG conformance.
