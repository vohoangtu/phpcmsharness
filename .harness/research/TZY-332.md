# TZY-332: Heading hierarchy review for the cart page

## Question
Should the checkout heading in `src/Presentation/Views/frontend/shop/cart.php` remain an `<h3>` after the cart page's `<h1>`, once the frontend layout and partials are considered?

## Findings

- W3C WAI's Headings tutorial says heading ranks should follow the content hierarchy; a skipped rank can be confusing when a subsection begins. It also explicitly allows skipping a rank when a subsection is ending, and says fixed page regions such as sidebars may keep a consistent rank across pages. **Effect:** inspect meaningful relationships in rendered page context rather than mechanically changing every apparent jump.
- W3C WAI's WCAG 2.1 technique G141 recommends properly nested headings as a way to organize page sections. It labels techniques as examples rather than mandatory requirements. **Effect:** treat a detected jump as a review signal, not a standalone WCAG conformance verdict.
- The cart template contains a page-level `<h1>` (“Giỏ hàng & Thanh toán”) and, in the populated-cart branch, a checkout form region headed by `<h3>` (“Thông tin Đặt hàng”). There is no intervening `<h2>` section heading in this template. The frontend layout contributes navigation links, a `<main>` wrapper, and footer content but no headings. The checkout region is a direct section under the page title, so `<h2>` better expresses that structure. **Effect:** change this heading to `<h2>` while retaining its existing class-free markup and text; no visual style should dictate its semantic rank.
- The empty-cart branch does not render the checkout region, so it has no associated heading to adjust. The finding is specific to this template's own structural section; the template's rendered page should still be considered together with the frontend layout/partials.

The verification suite can check the template's output; no browser or screen-reader inspection was performed. This is a focused semantic adjustment, not a WCAG compliance determination.
