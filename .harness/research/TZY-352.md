# TZY-352: Image dimensions in the admin media library

**Research date:** 2026-11-09

## Question

How should the admin media library reserve thumbnail space while images load, and when is it correct to emit HTML `width` and `height` attributes?

## Findings and impact

1. The HTML image `width` and `height` attributes are integer pixel dimensions. Browsers can use their ratio before the image loads to reserve space; the dimensions should correspond to the image resource (or the largest resource in a responsive `srcset`). This supports emitting the stored intrinsic dimensions only when both are known and positive. It does not support inventing defaults. Source: MDN, “`<img>`: The Image Embed element,” https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img (accessed 2026-11-09; page does not state a publication date).
2. CSS `aspect-ratio` or another layout rule can reserve image space without HTML dimensions. `web.dev` specifically calls out CSS `aspect-ratio` as an alternative. The local admin stylesheet instead gives `.wp-media-thumb img` `width: 100%` and a fixed `height: 140px`, which establishes a stable thumbnail box even when legacy media records have no dimensions. `object-fit: cover` keeps the crop visually contained. Source: web.dev, “Optimize Cumulative Layout Shift,” https://web.dev/articles/optimize-cls?hl=en (published approximately 6.5 years before access, according to the search result; accessed 2026-11-09).
3. A fixed-height thumbnail is a deliberate crop layout rather than a representation of the original image ratio. Keeping the CSS box and the true HTML dimensions (when available) is appropriate: CSS controls the rendered thumbnail, while attributes provide the image's intrinsic ratio early in loading. The focused regression should cover both valid dimensions and absent dimensions, and confirm the CSS reservation remains present. Source: MDN, “Understanding and setting aspect ratios,” https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Box_sizing/Aspect_ratios (accessed 2026-11-09; page does not state a publication date).

## Repository evidence

- `src/Presentation/Views/admin/media/index.php` emits the media record's dimensions only when both values are non-null and positive; it does not substitute guessed values.
- `src/Infrastructure/Storage/LocalMediaStorageAdapter.php` reads raster dimensions from the uploaded asset with `getimagesize()` and rejects files whose dimensions cannot be determined.
- `public/assets/css/admin.css` reserves a 100%-wide by 140px thumbnail box with `object-fit: cover`.
- The repository contains no checked-in uploaded image assets to inspect. Runtime media dimensions are persisted with each media record.
- This static review establishes that the thumbnail box is reserved by CSS; it does not measure browser layout shifts or Core Web Vitals.
