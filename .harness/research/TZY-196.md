# TZY-196 — Regression coverage for TaxonomyService

**Research date:** 2026-11-08

## Question

How should the public use cases of `TaxonomyService` be tested in this repository so the coverage is meaningful, isolated from SQLite, and detected by the existing verification gate?

## Findings and implementation impact

1. PHP interfaces define public method contracts that interchangeable implementations must fulfill. `CategoryRepositoryPort` and `TagRepositoryPort` are the seams used by `TaxonomyService`; small in-memory fakes can isolate service behavior and record persisted entities and calls. **Impact:** exercise the service through its constructor-injected ports, without adding a database dependency or changing application behavior. Source: [PHP Manual — Object Interfaces](https://www.php.net/manual/en/language.oop5.interfaces.php) (accessed 2026-11-08).
2. PHPUnit's test-double guidance describes stubs as a way to control collaborator results and isolate the system under test, and mocks as a way to verify collaborator interactions. This repository does not use PHPUnit for its current gate; `tests/hexagon_test.php` is a self-running script with `assertTrue()`. **Impact:** follow the existing runner convention with deterministic in-memory fakes, meaningful value and call assertions, and ensure the test is in `tests/hexagon_test.php` so Gate 3 runs it. Source: [PHPUnit 12.5 Manual — Test Doubles](https://docs.phpunit.de/en/12.5/test-doubles.html) (accessed 2026-11-08).
3. Repository inspection: `TaxonomyService` exposes category list/by-ID/by-slug, save/delete category, all-tags, save/delete tag. Its save methods trim inputs, build slugs through `Slug`, restrict category type to `post`/`product` (defaulting invalid values to `post`), pass an existing category ID when provided, and return IDs from the repository. `CategoryRepositoryPort` and `TagRepositoryPort` expose these operations, and SQLite adapters persist the entities. **Impact:** regression checks should assert forwarding/return behavior, normalized entity fields (including Vietnamese slug conversion), category update identity and type fallback, and delete delegation. No service or adapter change is needed for the requested coverage.
4. Existing suite already imports `TaxonomyService` but has no exercise/assertion for it. The harness uses `assertTrue()` and includes fake implementations inline. **Impact:** add port fakes and focused assertions directly in the existing test script, preserving the current test command and project structure.
