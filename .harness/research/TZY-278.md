# TZY-278 Research: unnamed form control in the admin dashboard

**Research date:** 2026-11-08

## Question

Does the checkbox in `src/Presentation/Views/admin/dashboard.php` near line 91 need a `name` so its value reaches the server, or is it only a UI trigger whose state is already represented by other form fields?

## Findings

1. The WHATWG HTML Standard defines a form control's `name` as the name used for form submission. During construction of form data, controls with no `name` or an empty `name` are skipped. A named checkbox contributes its name and value (defaulting to `on`) when included in the form data. This means adding a name to this checked toggle would submit an extra checkbox value; it would not be a harmless accessibility or validation change.
2. The dashboard toggle form already includes named hidden fields for `module_key`, `redirect_to`, and `state`. Its checkbox has no `name` and invokes `this.form.submit()` on change. `ModuleController::toggle()` reads `module_key` and `state`; `state` explicitly carries the desired next state. The checkbox is therefore an interaction trigger and does not need its own submitted value.
3. `tests/hexagon_test.php` already has a focused regression assertion that the quick-toggle checkbox has no `name`, triggers submission, and that the named hidden fields provide the values consumed by `ModuleController`. This matches the intended behavior and guards against accidentally adding an extra checkbox parameter.

## Decision and effect on implementation

No template or controller change is warranted. The static finding correctly observes a control without a static `name`, but this particular control is intentionally not submitted; the required module state is supplied by hidden fields. Adding `name` could change the request payload and break or confuse state handling. Preserve the markup and its existing regression coverage, then run the requested harness verification.

Code review confirmed that `ModuleController::toggle()` reads `module_key` and `state`, and the dashboard form provides both as named hidden inputs (plus `redirect_to`). `tests/hexagon_test.php` already contains a focused regression assertion that the checkbox remains unnamed, triggers form submission, and that the named hidden fields carry the values read by the handler. This coverage was retained; no additional test or source edit was needed for this review-only finding.

## Sources

- WHATWG, *HTML Living Standard*, “The `input` element,” including the `name` attribute definition. Accessed 2026-11-08: https://html.spec.whatwg.org/multipage/input.html
- WHATWG, *HTML Living Standard*, “Constructing the entry list,” which skips a control without a `name` and defines checkbox entry construction. Accessed 2026-11-08: https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#constructing-the-entry-list

## Limitations

The research uses the normative HTML Standard and repository source/tests. No browser automation or live HTTP request was needed to determine the server contract; runtime behavior is covered here by the static form wiring and existing regression assertion.
