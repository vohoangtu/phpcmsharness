# TZY-181 — AutoTopic brainstorm and implementation report

**Ngày khảo sát:** 2026-11-08  
**Câu hỏi:** Có thể cải thiện AutoTopic để các đề tài phản ánh chính xác hơn việc tuân thủ quy ước PHP và Hexagonal của repository như thế nào?

## Khảo sát repository

`CmsTopicGenerator` phát hiện marker TODO/FIXME/HACK/XXX, PHP file thiếu `strict_types`, Application Service chưa được tham chiếu trong tests và file nguồn có kích thước là outlier P90. Hàm `hasStrictTypesDeclaration()` tokenize file để tránh nhầm comment/string, nhưng hiện duyệt mọi token `T_DECLARE`; nó không yêu cầu directive là câu lệnh đầu tiên của file hay ở top-level. Vì vậy một declaration xuất hiện muộn hoặc trong block có thể làm AutoTopic kết luận nhầm file đã bật strict typing. Các regression hiện có chỉ kiểm tra directive trong comment/string và declaration đúng chuẩn.

## Ý tưởng đã cân nhắc

1. **Xác minh `strict_types` là khai báo đầu tiên ở top-level.** Sửa parser token hiện tại và thêm fixture cho declaration sai vị trí. Phạm vi nhỏ, trực tiếp khắc phục false negative trong một tín hiệu P0 hiện có.
2. **Mở rộng kiểm tra độ phủ sang SQLite adapters.** Có thể phát hiện adapter chưa có coverage trực tiếp, nhưng repository hiện kiểm thử gián tiếp qua services/containers; chỉ nhìn tên class trong test sẽ tạo false positive và cần mô hình quan hệ phức tạp hơn.
3. **Cải thiện tín hiệu outlier bằng giới hạn quy mô / bỏ qua file sinh tự động.** Có thể tránh xếp file sinh ra vào đề tài refactor, nhưng chưa thấy quy ước đánh dấu file generated thống nhất trong repository và cần định nghĩa thêm quy tắc nhận diện.

## Lựa chọn và tiêu chí

Chọn ý tưởng 1. Tiêu chí: bằng chứng là một thiếu sót cụ thể trong logic hiện hữu; tác động lên chất lượng backlog rõ; thay đổi giới hạn ở AutoTopic và kiểm thử; không đổi format, mức ưu tiên hay ranking các đề tài; regression có thể chứng minh cả positive và negative cases.

## Nghiên cứu nguồn

- PHP Manual, [Type declarations — Strict typing](https://www.php.net/manual/en/language.types.declarations.php), truy cập 2026-11-08: tài liệu xác nhận strict mode được bật theo từng file bằng directive `declare(strict_types=1)` và ví dụ dùng khai báo ở đầu script. Điều này khiến vị trí khai báo có ý nghĩa đối với việc phân loại một file là strict.
- PHP Manual, [declare](https://www.php.net/manual/en/control-structures.declare.php), truy cập 2026-11-08: `declare` cấu hình directive cho code và được xử lý ở giai đoạn biên dịch. Áp dụng vào AutoTopic: chỉ nhận diện directive đầu tiên trong phần PHP, trước các câu lệnh thường, thay vì khớp mọi token `T_DECLARE` trong file.
- PHP Manual, [token_get_all](https://www.php.net/manual/en/function.token-get-all.php), truy cập 2026-11-08: hàm tokenize bằng Zend lexical scanner và trả token id, nội dung, số dòng. Áp dụng: giữ cách phân tích token hiện tại để bỏ qua văn bản trong comment/string, rồi kiểm tra cấu trúc token ở đầu file.

Các trang tài liệu trên không nêu ngày xuất bản/cập nhật cụ thể trong nội dung đã truy cập; ngày truy cập được ghi rõ. Nghiên cứu chỉ dùng tài liệu PHP chính thức, không dựa vào nguồn bên thứ ba.

## Thay đổi dự kiến

Sửa `hasStrictTypesDeclaration()` để chỉ chấp nhận `declare(strict_types=1);` đầu tiên ở cấp file, sau whitespace/comment của thẻ mở PHP. Thêm regression cases để directive nằm sau câu lệnh hoặc trong block không che giấu thiếu hụt. Giữ nguyên fingerprint, nội dung, priority và thứ tự AutoTopic.
