# TZY-301: Reduced motion in frontend CSS

- **Research date:** 2026-11-08
- **Question:** Does the loaded public frontend stylesheet contain motion that should adapt to the operating system's reduced-motion preference, and what is an appropriate CSS implementation?

## Findings

1. WCAG's Understanding document for Success Criterion 2.3.3 describes animation from interactions as motion animation triggered by interaction that can be disabled, unless the animation is essential. It lists CSS `prefers-reduced-motion` as a sufficient technique, while noting that techniques are informative guidance rather than the only implementation. This means the stylesheet should honor the preference for spatial movement, while preserving interface function and essential feedback. Source: [W3C, Understanding SC 2.3.3: Animation from Interactions](https://www.w3.org/WAI/WCAG21/Understanding/animation-from-interactions) (accessed 2026-11-08).

2. The `prefers-reduced-motion: reduce` media query detects the user's system preference. A matching rule later in the cascade can override normal motion declarations. MDN describes the preference as minimizing non-essential motion, with scaling and panning called out as possible vestibular triggers. This supports a targeted override for transform movement rather than indiscriminately removing all visual state changes. Source: [MDN, `prefers-reduced-motion`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion) (accessed 2026-11-08).

3. The application layout links `/assets/css/frontend.css` in the frontend `<head>`, so this file is active on rendered frontend pages. Inspection found two short interaction transitions: a broad `transition: all 0.15s` and a `transform`/`box-shadow` transition at 0.15 seconds. There are no CSS keyframes or existing reduced-motion rules in this stylesheet. Since the broad transition can animate layout/transform changes and the second explicitly animates transform, the reduced-motion preference should disable those transitions. Preserve instantaneous hover colors, shadows, and other non-motion state feedback.

## Implementation decision

Append a narrowly scoped `@media (prefers-reduced-motion: reduce)` block to `public/assets/css/frontend.css` that turns off the existing interactive transitions. Add regression coverage checking that the loaded frontend stylesheet declares the preference and that the affected transition rules are covered. This addresses the detected motion without imposing a blanket rule on future animation or essential behavior.

## Research limitations

This was a source and stylesheet review, not a browser/device accessibility audit. CSS-level review does not establish WCAG conformance or whether any user is affected. The prompt's detector caveats apply: it does not inspect JavaScript motion or imported stylesheet behavior.
