# TZY-184 — AutoTopic phát hiện TODO trong HTML template comments

**Ngày khảo sát:** 2026-11-08  
**Câu hỏi:** AutoTopic có bỏ sót marker TODO/FIXME trong HTML comments của PHP views không, và có thể đọc comment mà không hiểu nhầm nội dung PHP/HTML thông thường là công việc cần làm?

## Khảo sát repository

`CmsTopicGenerator::findUnfinishedMarkers()` quét các file PHP trong `src`, `public`, `config`. Với PHP, `extractComments()` chỉ nhận token `T_COMMENT` và `T_DOC_COMMENT`. Các view trong `src/Presentation/Views` chứa markup HTML xen với PHP; HTML comments hiện hữu dùng `<!-- ... -->`, nhưng `token_get_all()` trả phần markup ngoài PHP là `T_INLINE_HTML`, không phải PHP comment. Do đó TODO đặt trong HTML comments của template sẽ không được phát hiện. Tín hiệu có thể mở rộng tại nhánh tokenizer PHP bằng cách chỉ quét `T_INLINE_HTML`, giữ nguyên xử lý token comment của PHP.

## Ý tưởng đã cân nhắc

1. **Phát hiện marker trong HTML comments ở PHP views.** Phân tích riêng các vùng `T_INLINE_HTML` và nhận diện đúng cặp `<!-- ... -->`; không quét text hay PHP string tùy tiện. Cải thiện tín hiệu AutoTopic trong thư mục view hiện có, thay đổi cục bộ và có thể kiểm thử positive/negative.
2. **Phân tích ngữ cảnh JavaScript regex literal trong scanner asset.** Có thể tránh false positive khi chuỗi `// TODO` hoặc `/* TODO */` xuất hiện trong regex literal. Tuy nhiên phân biệt regex với phép chia yêu cầu nhiều trạng thái cú pháp; chi phí và rủi ro lớn hơn một lát cắt nhỏ.
3. **Phát hiện coverage thiếu cho Controller/Adapter ngoài Application Service.** Mở rộng heuristic từ services sang các lớp inbound/outbound khác có thể tăng ích lợi, nhưng cách kiểm thử qua container/flow gián tiếp khiến suy luận theo tham chiếu tên lớp dễ báo sai và vượt mức phân tích hiện có.

## Lựa chọn và tiêu chí

Chọn ý tưởng 1. Tiêu chí: xác nhận bằng file và đường đi cụ thể trong repository; tăng độ bao phủ của heuristic marker vốn đã hỗ trợ PHP; không thay đổi schema, fingerprint, thứ tự ưu tiên hoặc behavior của comment PHP; nhận diện có ranh giới HTML rõ và có regression kiểm tra comment tiếng Việt nhiều dòng, literal/text thường cùng comment không đóng hoặc không chứa marker.

## Nghiên cứu nguồn

- PHP Manual, [`token_get_all()`](https://www.php.net/function.token-get-all), truy cập **2026-11-08**: hàm dùng lexical scanner của Zend và tài liệu minh họa text ngoài thẻ PHP được trả thành `T_INLINE_HTML`, không phải `T_COMMENT`. Áp dụng: khi xử lý PHP template, cần tách phần markup token ra khỏi PHP code trước khi tìm HTML comments.
- PHP Manual, [List of Parser Tokens — `T_INLINE_HTML`](https://www.php.net/manual/en/tokens.php), truy cập **2026-11-08**: `T_INLINE_HTML` là text ở ngoài PHP. Áp dụng: chỉ kiểm tra token này để không dò HTML comment bên trong PHP strings/comments.
- WHATWG, [HTML Standard — Comments](https://html.spec.whatwg.org/multipage/syntax.html#comments), truy cập **2026-11-08**: cú pháp comment HTML bắt đầu `<!--` và kết thúc `-->`, với các giới hạn nội dung. Áp dụng: marker chỉ được trích từ nội dung comment HTML đã đóng; không khớp toàn bộ inline markup.

Các trang đã kiểm tra không nêu rõ ngày xuất bản/cập nhật trong phần nội dung được kiểm tra; URLs chính thức và ngày truy cập được ghi ở trên. Nghiên cứu web khả dụng.

## Kế hoạch triển khai

Mở rộng xử lý PHP trong `extractComments()` để đọc HTML comment blocks từ từng `T_INLINE_HTML` token, tính dòng bắt đầu chính xác rồi trả về qua cùng pipeline marker hiện tại. Bổ sung hồi quy cho HTML comment nhiều dòng có marker và cho marker text nằm ngoài comment hoặc trong PHP string; sau đó chạy `./bin/tuzygent verify`.
