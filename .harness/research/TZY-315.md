# TZY-315 Research: frontend meta descriptions

- **Question:** Should the shared frontend HTML layout emit a meta description, and what should supply its content so it represents the rendered page?
- **Research date:** 2026-11-08
- **Scope:** Google Search Central guidance and the repository's current frontend rendering flow.

## Findings

1. Google says search snippets are primarily generated automatically from visible page content. It sometimes uses a page's `meta description` when that is a more accurate description. Google may vary snippets by query, so adding this tag does not guarantee its use or a ranking improvement.
   - Source: https://developers.google.com/search/docs/appearance/snippet
   - Date shown by source: no publication/update date surfaced in the available search result; accessed 2026-11-08.
   - Effect on feature: emit a useful description in the rendered `<head>`, while treating it as optional input to search snippets rather than a directive controlling Google.

2. Google recommends distinct descriptions that accurately summarize each page. For database-driven content, programmatically generated descriptions can be appropriate when they are readable, varied, and based on page-specific data. Reusing one description across every page is not helpful.
   - Source: https://developers.google.com/search/docs/appearance/snippet
   - Date shown by source: no publication/update date surfaced in the available search result; accessed 2026-11-08.
   - Effect on feature: have the shared layout accept page-specific description text from the renderer/controller, with a concise per-page fallback where no explicit description exists; use an article excerpt or product short description for detail pages, rather than blindly reusing one global string.

## Repository observations

- `src/Presentation/Views/layouts/frontend.php` is the shared HTML layout and currently renders `<title>` but no meta description.
- `ViewRenderer::renderFrontend()` extracts supplied page data before rendering the view and shared layout, so a description can flow through without changing persistence or domain layers.
- Article detail content exposes `$post->excerpt`; product detail content exposes `$product->shortDescription`. The frontend controllers already have these entities when preparing each detail page.
- The existing test suite is `tests/hexagon_test.php`; it already reads the frontend layout source, so a focused rendered-markup regression can be added in that suite.

## Research limitations

Only Google's official guidance was used. It explains search behavior and authoring guidance but cannot predict whether Google will choose a supplied description for any specific query or whether the change will affect ranking.
