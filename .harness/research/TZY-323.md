# TZY-323: Heading hierarchy review for the admin product form

- **Question:** Do the headings in `src/Presentation/Views/admin/products/form.php` form a meaningful hierarchy once the template is rendered, and what targeted change is justified by authoritative guidance?
- **Research date:** 2026-11-08
- **Scope:** W3C WAI guidance and the WHATWG HTML Standard; template source inspection is not a substitute for inspecting the final page DOM.

## Findings and effect on the feature

1. W3C WAI's [Headings tutorial](https://www.w3.org/WAI/tutorials/page-structure/headings/) explains that heading ranks communicate section relationships, and recommends avoiding skipped ranks while creating subsections. It also explicitly permits a rank skip when a new section closes a prior subsection, and says fixed page regions such as sidebars may keep consistent heading ranks independent of the content area. **Effect:** treat a source-level `h1`→`h3` signal as a review hint rather than a definitive error; inspect whether each heading begins a subsection and account for the sidebar.
2. W3C's [Easy Checks: Headings](https://www.w3.org/WAI/test-evaluate/easy-checks/headings/) advises checking that marked-up headings represent conceptual sections and that the hierarchy is meaningful; an `h1` followed by consecutively ranked subsections is an illustrative pattern, not an absolute requirement. **Effect:** do not change tags just to alter visual styling; preserve the existing classes and assess section meaning.
3. The [WHATWG HTML Standard, heading content](https://html.spec.whatwg.org/multipage/dom.html#heading-content) defines `h1` through `h6` as heading content that defines a section heading. **Effect:** page structure should use semantic heading elements and their rank, with presentation handled independently.
4. W3C's [Understanding WCAG 2.4.6: Headings and Labels](https://www.w3.org/WAI/WCAG21/Understanding/headings-and-labels) requires headings and labels to describe topic or purpose; it does not make every skipped rank a WCAG failure. **Effect:** retain this as a structural review and regression task; do not claim a conformance violation from the detector alone.

## Repository assessment

The product form emits one page-level `h1`, then multiple card headings currently marked `h3`. They label peer sections in the main editor (product data and detailed description) and in the fixed sidebar (publishing, categories, tags, featured image). The template is included in an admin layout; the detector does not resolve that layout or conditional branches. Based on the visible page title and peer-section roles, change the card heading tags to `h2` while preserving classes and CSS. Add coverage against rendered product-form markup, including the conditional sidebar section, so semantic hierarchy is checked without relying only on source text.

## Limitations

Research used available W3C and WHATWG pages. No browser-driven end-user page audit was performed; the regression test will render the view in its application context, but will not reconstruct an arbitrary external layout. Recommendations are guidance for heading structure, not a claim that a WCAG failure exists.
