# TZY-185 — AutoTopic phát hiện marker trong CSS inline comments

**Ngày khảo sát:** 2026-11-08  
**Câu hỏi:** AutoTopic có bỏ sót marker bảo trì trong comment CSS hợp lệ nằm cùng dòng với quy tắc CSS không, và có thể phát hiện chúng mà vẫn bỏ qua marker bên trong chuỗi CSS?

## Khảo sát repository

`CmsTopicGenerator::findUnfinishedMarkers()` quét `.css` trong `src`, `public`, `config`. Scanner ở `extractComments()` phân biệt chuỗi với comment, nhưng chỉ chấp nhận `/* ... */` nếu phần trước comment trên cùng dòng là whitespace (`trim(substr(...)) === ''`). Vì thế comment CSS inline như `.button { color: red; } /* TODO: restore contrast */` bị bỏ qua dù đây là comment CSS hợp lệ. Test hiện có xác minh comment block độc lập được tìm thấy và marker trong string CSS bị bỏ qua; chưa có ca inline.

## Ý tưởng đã cân nhắc

1. **Phát hiện CSS block comments inline.** Cho phép scanner CSS thu thập block comment ở bất kỳ vị trí hợp lệ nào trong dòng, trong khi vẫn tôn trọng quote/escape; bổ sung hồi quy cho comment sau declaration, nhiều comment trên một dòng, và marker trong chuỗi. Đây là một lỗ hổng AutoTopic có thể chứng minh trực tiếp.
2. **Phân tích JavaScript regular-expression literals.** Scanner JS thủ công có thể nhầm dấu gạch chéo trong regex thành comment. Khắc phục chính xác đòi hỏi phân biệt regex literal với phép chia theo ngữ cảnh cú pháp JS, tăng đáng kể độ phức tạp và nguy cơ false positive.
3. **Phát hiện CSS `!important` như tín hiệu bảo trì.** Có thể đề xuất xem xét declaration dùng `!important`, nhưng đây thường là chủ ý hợp lệ và tần suất không tự chứng minh lỗi; heuristic có nguy cơ tạo backlog nhiễu.

## Tiêu chí lựa chọn và đề tài được chọn

Chọn ý tưởng 1 theo các tiêu chí: khoảng trống được tái hiện từ mã hiện hữu; mở rộng chính xác một nguồn AutoTopic đang hỗ trợ; không đổi schema, ưu tiên hay fingerprint; kiểm tra được cả positive và negative cases; rủi ro parser thấp vì CSS chỉ dùng block comment `/* ... */` và scanner đã theo dõi quote/escape.

## Nghiên cứu nguồn và ảnh hưởng tới thiết kế

- W3C, [CSS Syntax Module Level 3](https://www.w3.org/TR/css-syntax-3/), bản hiện hành được trang ghi nhận xuất bản/cập nhật tháng trước, truy cập **2026-11-08**. Đặc tả mô tả quá trình tokenize stylesheet; vị trí comment không bị giới hạn là đầu dòng. Ảnh hưởng: không dùng điều kiện “đầu dòng” như ranh giới hợp lệ của CSS comment.
- MDN, [Comments — CSS](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Syntax/Comments), truy cập **2026-11-08** (trang ghi nhận crawl tuần trước). Tài liệu nêu cú pháp `/* ... */`, dùng cho comment một hoặc nhiều dòng, và comment có thể đặt nơi whitespace được phép trong stylesheet. Ảnh hưởng: detector nhận diện comment inline sau code CSS, nhưng chỉ lấy nội dung nằm trong cặp comment.

Các nguồn trên xác nhận cú pháp/vị trí comment, không đặt quy tắc riêng cho marker TODO. Đề tài dùng TODO/FIXME/HACK/XXX làm quy ước bảo trì hiện có của repository.

## Kế hoạch triển khai

Điều chỉnh scanner CSS trong `CmsTopicGenerator::extractComments()` để không loại block comment chỉ vì có nội dung code đứng trước nó trong cùng dòng; giữ nguyên bộ theo dõi quote/escape để không nhận comment-like text trong string. Thêm hồi quy CSS inline/multiple comments và negative cases cho chuỗi, đồng thời xác minh line number, target identity và behavior hiện có. Chạy `./bin/tuzygent verify`.
