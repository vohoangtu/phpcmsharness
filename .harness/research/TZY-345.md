# TZY-345: Image dimensions in the admin product form

**Research date:** 2026-11-09

## Question

Do the two `<img>` elements in `src/Presentation/Views/admin/products/form.php` need intrinsic `width` and `height` attributes, or does the rendered layout already reserve space? Which values are safe for user-selected product and media images?

## Findings and implementation impact

1. The HTML Standard defines `width` and `height` on `<img>` as dimensions of the visual content, and maps them to width, height, and an aspect ratio used during layout. The dimensions are not intended to stretch an image. This means markup values should describe the selected resource's real display dimensions (or its true ratio), not an arbitrary common crop. **Impact:** do not add guessed intrinsic values to these templates, whose image URLs are dynamic.
   - Source: https://html.spec.whatwg.org/multipage/embedded-content.html#dimension-attributes (living standard; accessed 2026-11-09)

2. MDN recommends setting both attributes so browsers can calculate an image's aspect ratio before the resource loads and reserve space, and notes that CSS sizing can also affect image presentation. **Impact:** confirm the actual CSS/layout reservation on both image paths and protect that behavior with a focused regression assertion.
   - Source: https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img (accessed 2026-11-09)

3. web.dev's CLS guidance says either `width`/`height` or CSS `aspect-ratio` (or a similar reservation mechanism) can allocate the image's space before load. It also explains that dimensions should match the true ratio and that CSS can make images responsive. **Impact:** the product form's featured preview uses CSS `width: 100%` plus `aspect-ratio: 16 / 9`; the media picker uses a fixed CSS height and `object-fit: cover`. Those rules reserve layout boxes without asserting that arbitrary source assets have those intrinsic dimensions. Keep the existing visual crop and verify the rules remain applied.
   - Source: https://web.dev/articles/optimize-cls?hl=en (published approximately 2020; accessed 2026-11-09)

## Repository inspection

- The featured preview URL comes from a saved product or is changed by the admin's URL picker, and media thumbnails use `MediaFile::filePath`; neither source has a single statically known intrinsic dimension in this template.
- `public/assets/css/admin.css` reserves a 16:9 box for `.wp-featured-preview img` and a `55px` high crop for `.wp-media-mini-grid img` (`object-fit: cover`).
- The main preview is hidden with `display:none` only when its URL is empty; when shown, it remains inside the reserved preview container.
- No browser layout-shift measurement is available in the current verification harness, so this report establishes the CSS reservation and does not claim a measured CLS improvement.

## Conclusion

Keep intrinsic dimension attributes unset for these dynamic sources; adding a guessed ratio would be misleading. Add product-form regression coverage that confirms the rendered preview and media-picker images remain dimension-attribute-free and that their CSS reservation rules continue to exist. The change protects existing behavior and makes the reason for it explicit.
